## 1. 文档说明

### 1.1 编写目的

本文档将已确认的产品需求整理为可直接指导开发的规格说明，覆盖以下内容：

- 产品目标、边界与首版范围；
- 键盘和鼠标输入的统计语义；
- 前台界面、实体键盘和鼠标的可视化方案；
- UTC 时间、时区、聚合粒度、覆盖率和活跃指标；
- SQLite 数据结构、缓存、持久化、归档与故障恢复；
- Windows 后台采集、异步执行和性能约束；
- 安装目录、数据目录、备份、恢复、删除和升级策略；
- 本地 CI/CD、自动化测试、性能门禁与发布验收；
- 风险、限制、测试矩阵和完成定义。

若实现细节与本文档冲突，以本文档中的冻结需求为准。确需变更时，应先更新本文档和对应测试，再修改实现。

### 1.2 需求优先级

- P0：隐私、计数正确性、数据安全、不中断系统输入、UTC 时间口径、后台稳定性。
- P1：104/75 键盘与五键鼠标可视化、趋势图、历史查询、主题、安装与本地 CI/CD。
- P2：2.5D 视觉质量、前台动画、更多配色、易用性细节。
- 非首版：联网、排行榜、账户、云同步、自动更新、更多键盘配列、任意渐变编辑器、精确鼠标移动距离。

### 1.3 术语

| 术语 | 定义 |
|---|---|
| 物理按下 | 一个键从未按下状态进入按下状态；长按产生的系统连发不重复计数 |
| 鼠标按键 | 左键、右键、中键、前侧键、后侧键的独立按下 |
| 滚轮格数 | Raw Input 滚轮增量累计达到 120 时产生的一格 |
| 5 分钟桶 | 按 UTC+0 对齐到 5 分钟边界的最小持久化统计单位 |
| 小时桶 | 按 UTC+0 整点对齐的永久聚合统计单位 |
| 覆盖率 | 程序实际处于可采集状态的时间占查询时间范围的比例 |
| 已使用天数 | 从首次成功开始记录之日起，按当前有效显示时区计算的自然日跨度，包含没有输入的日期 |
| 已活跃天数 | 活跃分数严格大于 1000 的自然日数量 |
| 有效显示时区 | 当前 Windows 时区为整数小时偏移时使用该时区，否则回退 UTC+0 |

## 2. 产品概述

### 2.1 产品定位

InputAtlas 是一个轻量、完全离线的 Windows 后台输入统计工具。它在不拦截、不修改、不保存输入内容的前提下，持续统计键盘物理按键、鼠标按键和滚轮格数，并通过实体键盘、鼠标热力图及时间序列图表展示个人输入习惯。

产品强调四点：

1. 计数可信：长按只记一次，左右修饰键和主键区/小键盘键位可分离。
2. 隐私明确：只保存聚合计数与覆盖时间，不保存任何可还原输入内容的数据。
3. 后台轻量：采集回调极短，数据库、图表和日志全部异步，不阻塞操作系统或其他程序。
4. 展示直观：首页绘制实体 104 或 75 配列键盘、通用五键鼠标和热力图，前台输入时有即时动画。

### 2.2 首版目标

- 支持 ANSI 104 键标准配列。
- 支持用户参考图中确认的 75% 配列。
- 支持通用五键鼠标轮廓及纵向、横向滚轮统计。
- 记录每个键、每个鼠标按键和每个滚轮方向的累计次数。
- 提供今日指标、历史区间、趋势图、热力图和按键详情。
- 以 UTC+0 记录和合并，按系统时区动态展示。
- 5 分钟为最小数据粒度，超过保留期限后合并为 1 小时永久数据。
- 支持自定义安装位置，程序和数据库目录位于同一安装根目录下。
- 提供本地 CI/CD 和尽可能完整的自动化验证。
- 发布目录内置 .NET 10 Desktop Runtime，安装后可在未预装 .NET 的离线设备上运行。

### 2.3 非目标

首版明确不做以下功能：

- 不记录键入文字、剪贴板、按键顺序、组合键关系或逐事件时间戳。
- 不记录鼠标位置、轨迹、点击坐标、移动距离或屏幕内容。
- 不区分正在使用的应用、进程、窗口或网页。
- 不上传数据，不提供账户、云同步、排行榜、遥测或崩溃上报。
- 不做系统服务，不申请管理员权限，不采集安全桌面、登录界面或其他用户会话。
- 不支持非整数小时偏移时区的本地日历聚合；此时统一回退 UTC+0。
- 不尝试识别所有厂商私有鼠标按键。
- 不提供便携版。
- 不在首版提供在线自动更新。

## 3. 命名与技术基线

### 3.1 命名

| 项目 | 名称 |
|---|---|
| 产品名 | InputAtlas |
| 中文名 | 输入图谱 |
| 主进程 | InputAtlas.exe |
| 主数据库 | inputatlas.db |
| 默认安装文件夹 | InputAtlas |
| 构建入口 | build.ps1 |

### 3.2 建议技术栈

- 语言与运行时：C#，.NET 10 LTS。
- 桌面 UI：WPF。
- 结构：轻量 MVVM，避免引入体积较大的完整框架。
- 输入采集：Win32 Raw Input。
- 本地数据库：SQLite。
- 图表：OxyPlot.Wpf 2.2.0，通过项目内薄适配层使用。
- 安装器：Inno Setup 7。
- 目标架构：win-x64。
- 发布模式：self-contained，将 .NET Desktop Runtime 打包进应用。

选择这些技术时，应用体积、空闲资源、可维护性和 Windows 原生兼容性应优先于跨平台能力。

### 3.3 架构原则

- 采集、聚合、持久化、查询、渲染彼此解耦。
- 输入采集线程不得直接访问数据库、磁盘或 WPF 控件。
- 所有跨线程通信使用有界队列、原子计数或快照交换。
- 所有可能耗时的数据库、导出、备份、合并和图表查询均异步执行。
- UI 卡顿时只能降低动画或图表刷新频率，不能丢失输入计数。
- 所有网络相关依赖和代码均不进入首版。

建议的逻辑组件如下：

    Raw Input 专用线程
            │
            ▼
    物理状态机与输入映射
            │
            ▼
    内存原子计数器 / 当前 5 分钟桶
            │
      ┌─────┴───────────┐
      ▼                 ▼
    UI 快照发布      异步持久化队列
      │                 │
      ▼                 ▼
    热力图与动画      SQLite + 备份 + 合并

## 4. 隐私与安全边界

### 4.1 允许保存的数据

程序只允许保存以下数据：

- 5 分钟或 1 小时时间桶的 UTC 起始时间；
- 时间桶内各稳定输入 ID 的次数；
- 时间桶覆盖秒数；
- 数据库模式版本、首次使用时间和必要的应用元数据；
- 用户设置，如主题、配列、保留策略、窗口状态；
- 不含输入事件细节的运行日志。

### 4.2 严禁保存的数据

无论调试、异常诊断还是正式发布，均不得保存或输出：

- 用户输入的字符、文本和密码；
- 剪贴板内容；
- 按键先后顺序或可重放的事件序列；
- 单次按键、点击或滚轮事件的精确时间戳；
- 组合键、快捷键和键之间的关联；
- 当前窗口标题、进程名、应用名、网页或文档；
- 鼠标坐标、轨迹、移动距离和点击位置；
- 键盘或鼠标设备名、设备路径、序列号和稳定设备标识；
- 屏幕截图、录屏、麦克风、网络请求内容；
- 可用于还原用户行为细节的原始事件文件。

### 4.3 完全离线

- 首版不得发起任何网络连接。
- 不包含遥测、崩溃上传、远程字体、远程图片、在线账户、云同步和自动更新。
- 安装、首次运行、日常运行、导出、备份和恢复均可完全离线完成。
- 未来排行榜属于独立后续需求，首版不预埋账号、上传协议或常驻网络模块。

### 4.4 日志隐私

日志记录运行状态和性能，不记录输入内容。严禁在日志中出现：

- 键名、扫描码、虚拟键码；
- 单次鼠标按键或滚轮事件；
- 鼠标坐标；
- 输入顺序；
- 设备路径和设备名称；
- 窗口、进程、文件或文本内容。

## 5. Windows 输入采集

### 5.1 采集方式

使用 Win32 Raw Input：

- 键盘注册 RIDEV_INPUTSINK。
- 鼠标注册 RIDEV_INPUTSINK。
- 通过隐藏的 message-only window 接收 WM_INPUT。
- 窗口和消息循环运行在独立专用线程。
- 不使用 WH_KEYBOARD_LL 或 WH_MOUSE_LL 低级钩子。
- 不设置 RIDEV_NOLEGACY，避免改变其他应用收到输入的方式。
- 不拦截、不吞掉、不重写、不延迟 Windows 快捷键和其他输入。

### 5.2 回调热路径

WM_INPUT 处理路径只允许执行：

1. 读取原始输入结构；
2. 映射为稳定输入 ID；
3. 更新按下状态或滚轮余量；
4. 更新内存原子计数；
5. 发布轻量变更标记。

热路径严禁：

- SQLite 读写；
- 文件或日志写入；
- WPF 控件调用；
- 锁等待、阻塞等待或同步网络调用；
- 每事件对象分配；
- 格式化字符串；
- 每事件诊断日志；
- 任何可能触发不可控停顿的业务。

### 5.3 鼠标移动

- Raw Input 中的高频鼠标移动数据收到后立即忽略。
- 不统计移动次数、距离、轨迹或坐标。
- 忽略移动事件的路径必须零日志、尽量零分配。
- 需要以最高目标轮询率进行 8 kHz 压力测试。

### 5.4 键盘物理按下状态机

长按一个键只统计一次。状态机如下：

    初始：Released

    KeyDown 且状态为 Released
        计数加 1
        状态切换为 Pressed

    KeyDown 且状态为 Pressed
        判定为系统连发
        忽略，不计数

    KeyUp
        状态切换为 Released

这意味着赛车游戏中持续按住 W、方向键或其他按键时，只在首次物理按下时增加一次，不按系统连发次数累加。

以下时机必须清空所有 Pressed 状态，避免丢失 KeyUp 后产生永久按下：

- 应用启动；
- Raw Input 重新注册；
- 系统从睡眠或休眠恢复；
- 用户会话解锁；
- 手动暂停后恢复；
- 采集错误恢复；
- 其他会导致输入事件缺口的生命周期切换。

### 5.5 键位区分

键盘映射优先使用扫描码和扩展标志，不仅使用字符或虚拟键码。至少需要区分：

- 左 Ctrl / 右 Ctrl；
- 左 Shift / 右 Shift；
- 左 Alt / 右 Alt；
- 左 Win / 右 Win；
- 主 Enter / 小键盘 Enter；
- 主数字区 / 小键盘数字区；
- 主区方向与导航键；
- 能被 Raw Input 稳定识别的其他 ANSI 104 物理键。

Ctrl+C 只表示 Ctrl 和 C 各自增加一次，不保存二者是一个组合，也不保存它们的先后关系。

### 5.6 注入事件与宏

- 采用 Raw Input 后，普通软件模拟输入通常不会进入本统计边界，首版不额外建立注入事件识别系统。
- 键盘或鼠标固件在硬件层发出的宏事件无法可靠区分，应按普通硬件输入计数。
- 文档和界面隐私说明中需明确这一边界。

### 5.7 会话边界

- 仅统计当前登录用户普通桌面会话。
- 锁屏、登录界面、UAC 安全桌面、睡眠和休眠期间不统计。
- 不作为 Windows 服务运行。
- 不申请管理员权限。
- 当前会话中的远程桌面输入可以统计，但不区分其是否来自 RDP。
- 不跨 Windows 用户合并数据。

### 5.8 注册失败

Raw Input 注册失败时：

- 不得假装正在记录；
- 状态栏显示明确错误；
- 触发必要的低频系统通知；
- 首次引导不标记为完成；
- 后台按退避策略尝试恢复；
- 记录不含输入内容的错误码和生命周期日志。

## 6. 键盘配列

### 6.1 配列策略

首版只支持：

- ANSI 104；
- 已确认的 75% 配列。

配列由用户手动选择并记忆。程序不根据设备名或厂商自动识别键盘，也不保存硬件身份。

配列决定：

- 首页实体键盘的键位几何；
- 热力图落点；
- 键位选择和详情；
- 未显示键位如何归入“其他键”。

配列不改变底层按键计数。切换配列后，历史数据按稳定输入 ID 重新映射到当前视图。

### 6.2 ANSI 104

ANSI 104 应采用标准全尺寸美式布局，包括：

- 主键区；
- F1 至 F12 功能区；
- Print Screen、Scroll Lock、Pause；
- Insert、Home、Page Up、Delete、End、Page Down；
- 独立方向键；
- 完整数字小键盘；
- 左右修饰键分离；
- 主 Enter 和小键盘 Enter 分离。

### 6.3 75% 配列

75% 配列严格按照用户提供的参考图解释。图中带声波图案的部分为外壳装饰，不是特殊功能键，不得作为可统计键绘制。

逻辑行排列如下：

    第 1 行：Esc  F1  F2  F3  F4  F5  F6  F7  F8  F9  F10  F11  F12  Delete  Home

    第 2 行：Grave  1  2  3  4  5  6  7  8  9  0  -  =  Backspace  End

    第 3 行：Tab  Q  W  E  R  T  Y  U  I  O  P  [  ]  \  PgUp

    第 4 行：Caps  A  S  D  F  G  H  J  K  L  ;  '  Enter  PgDn

    第 5 行：LShift  Z  X  C  V  B  N  M  ,  .  /  RShift  Up

    第 6 行：LCtrl  LWin  LAlt  Space  Fn  RCtrl  Left  Down  Right

布局实现应在数据文件或布局模型中描述，不在渲染代码中硬编码大量坐标。每个键至少包括：

- 稳定输入 ID；
- 显示名称；
- 主副图例；
- 行、列或绝对几何；
- 键帽宽高单位；
- 映射可用性；
- 分组和辅助说明。

### 6.4 Fn 键限制

很多键盘的 Fn 键由固件内部处理，不会作为独立 Raw Input 按键发送给 Windows。因此：

- 75% 键盘中仍绘制 Fn 键以保持实体布局完整；
- 若系统不可观测，Fn 键标记为“系统不可用”或“无法统计”；
- 不把未收到事件错误解释为使用次数为零；
- 不通过厂商驱动、设备协议或内核方式强行读取。

### 6.5 布局外输入

当前选择的实体配列没有展示、但底层收到的有效键盘输入统一进入“其他键”统计。详情页可展示其总数，但不得泄露具体事件顺序。

## 7. 鼠标统计与绘制

### 7.1 外观

鼠标参考 Logitech PRO X SUPERLIGHT 2 的简洁、对称、轻量外形，但首版绘制必须：

- 使用通用无品牌轮廓；
- 不出现 Logitech、G、GPW、产品型号或商标；
- 不复制受保护的精细工业设计和材质贴图；
- 保留便于识别的左右键、滚轮和两枚侧键区域。

### 7.2 支持的鼠标按键

至少统计并独立展示：

- 左键；
- 右键；
- 中键，即滚轮按下；
- 前侧键；
- 后侧键。

所有鼠标设备的数据合并统计，不记录或展示设备身份。

### 7.3 滚轮

需要统计：

- 纵向向上格数；
- 纵向向下格数；
- 横向向左格数；
- 横向向右格数。

滚轮规则：

- Raw Input delta 的绝对累计值达到 120 时计为一格；
- 小于一格的余量只保存在内存；
- 余量与后续同方向输入继续累计；
- 持久化只保存完整整数格数；
- 向上和向下分开统计，不做净值抵消；
- 横向滚轮若设备和 Raw Input 支持，则同样按完整格数统计；
- 不统计厘米、像素、页面长度或所谓滚动距离；
- 不保存滚轮逐事件记录。

### 7.4 额外鼠标输入

- Windows Raw Input 能报告、但通用五键轮廓无法单独绘制的标准输入可归为“其他鼠标输入”。
- 厂商驱动和私有 HID 协议中的额外按键不在首版支持范围。
- 不依赖 Logitech G Hub，也不读取其配置。

## 8. 核心指标

### 8.1 首页主指标

首页最大的主数字定义为：

> 当前显示日期内的键盘物理按下总次数。

不得把鼠标点击和滚轮隐式混入该数字，以免“总计”含义模糊。

首页同时提供独立卡片：

- 今日键盘按键数；
- 今日鼠标按键数；
- 今日滚轮格数；
- 今日活跃分数；
- 已使用天数；
- 已活跃天数。

### 8.2 活跃分数

活跃分数计算方式：

    活跃分数
      = 键盘物理按下次数 × 1.0
      + 鼠标按键次数 × 1.0
      + 所有方向滚轮格数 × 0.2

首页必须使用小字说明：

> 活跃分数 = 键盘按键 + 鼠标按键 + 滚轮格数 × 0.2。

### 8.3 活跃天

活跃天定义为：

    当日活跃分数 > 1000

注意是严格大于 1000：

- 1000 不算活跃；
- 1000.2 算活跃。

由于滚轮倍率为 0.2，活跃分数可保留一位小数，内部建议使用整数五分之一单位，避免浮点误差：

    activity_units
      = keyboard_count × 5
      + mouse_button_count × 5
      + wheel_steps

    活跃条件：activity_units > 5000

### 8.4 已使用天数

- 起点为首次引导完成并成功注册 Raw Input 的 UTC 时间。
- 按当前有效显示时区换算为首次使用日期。
- 当前有效显示日期与首次使用日期做自然日包含式计算。
- 首次成功使用当天显示 1 天。
- 没有输入的日期仍计入已使用天数。
- 删除某个日期的统计数据不改变已使用天数。
- 只有“完整重置”会清除首次使用时间并重新计数。

### 8.5 已活跃天数

- 按查询时使用的有效显示时区动态聚合自然日。
- 每日活跃分数严格大于 1000 时计 1 天。
- 删除统计数据后重新计算。
- 时区从一个整数小时偏移切换到另一个整数小时偏移时，历史活跃天数允许变化。

## 9. 时间、时区和日期

### 9.1 存储时间

- 所有持久化时间统一使用 UTC+0。
- 时间戳建议存 Unix 秒的 64 位整数。
- 5 分钟桶按 UTC 秒向下对齐到 300 秒边界。
- 1 小时桶按 UTC 秒向下对齐到 3600 秒边界。
- 小时合并一律在 UTC+0 整点语义下进行。
- 数据库中不保存按本地时区预先切分的日、周、月汇总。

### 9.2 显示时区

程序读取当前 Windows 系统时区：

- 若当前 UTC 偏移是整数小时，整个界面使用该时区显示。
- 若当前 UTC 偏移不是整数小时，整个界面回退到 UTC+0。
- 回退时在界面显示“当前时区含非整数小时偏移，已使用 UTC+0”。
- 首次进入回退状态时允许发送一次低频通知。
- 不在不同页面混用本地时区和 UTC。

### 9.3 时区变化

当系统时区发生变化：

- 重新判断是否为整数小时偏移；
- 重新计算当前显示日期；
- 历史日、周、月按新有效时区动态聚合；
- 刷新首页、历史、趋势和活跃天数；
- 数据库原始 UTC 桶不修改。

### 9.4 夏令时

首版只接受当前偏移为整数小时的 Windows 时区。历史展示应通过 Windows 时区规则将各 UTC 时间点转换为本地时间，而不是给整段历史简单加一个固定偏移。若某一时间点规则产生非整数小时偏移，则该显示会话按 UTC+0 回退。

### 9.5 日期格式

- 中文界面日期统一使用 yyyy-MM-dd。
- 时间轴需要清楚标注当前有效时区，例如 UTC+8 或 UTC+0。
- 导出文件同时包含 UTC 时间和按导出时有效时区计算的显示时间。

## 10. 内存缓存与持久化

### 10.1 最小统计桶

- 5 分钟是首版最小持久化粒度。
- 当前 5 分钟桶在内存中持续累加。
- 时间边界以 UTC+0 对齐。
- UI 可以读取内存快照显示尚未落盘的最新数字。

### 10.2 检查点

- 每 30 秒发起一次异步检查点。
- 检查点把当前 5 分钟桶的完整快照 UPSERT 到 SQLite。
- 同一桶反复保存必须幂等，不得把已有值再次累加。
- 数据库写入不在 Raw Input 线程或 UI 线程上执行。
- 正常情况下崩溃最多损失约 30 秒尚未检查点的数据。

### 10.3 必须刷新的生命周期

以下时机应尝试异步或受限时长的立即保存：

- 进入新的 5 分钟桶；
- 用户选择退出；
- 手动暂停；
- 系统睡眠或休眠；
- 会话结束或注销；
- 应用升级前；
- 数据库备份、恢复或迁移前。

退出保存目标时间不超过 1 秒。系统结束会话时使用严格超时，不允许无限阻塞关机。

### 10.4 快照幂等

持久化记录为“该桶当前完整计数快照”，而非增量消息。推荐 UPSERT 语义：

    INSERT INTO bucket_5m (...)
    VALUES (...)
    ON CONFLICT(bucket_start_utc)
    DO UPDATE SET
        coverage_seconds = excluded.coverage_seconds,
        counts_json = excluded.counts_json,
        updated_utc = excluded.updated_utc;

重复写入相同快照结果不变，从而支持崩溃重试和数据库恢复后补写。

### 10.5 数据库故障缓存

数据库无法写入时采用退避：

    1 秒 → 2 秒 → 5 秒 → 10 秒 → 30 秒 → 60 秒

之后最多每 60 秒重试一次。

内存故障缓存上限取两者中先到者：

- 7 天未落盘数据；
- 16 MB 序列化前估算数据。

达到上限时：

- 停止并注销 Raw Input 采集；
- 明确显示“记录已暂停，数据库不可用”；
- 发送一次受冷却控制的关键通知；
- 不悄悄丢弃最旧数据；
- 不无限增长内存。

数据库恢复后：

- 按 UTC 从旧到新批量 UPSERT；
- 每批短事务；
- 恢复成功后再清除相应内存快照；
- 全部追平后恢复常规检查点。

### 10.6 覆盖秒数

每个桶保存 coverage_seconds：

- 5 分钟桶范围为 0 至 300；
- 1 小时桶范围为 0 至 3600；
- 程序成功注册采集且未暂停时，按单调时钟累计覆盖；
- 应用未运行、暂停、锁屏、睡眠、采集失败期间不增加覆盖；
- 数据库暂时不可写但采集仍工作时，覆盖继续增加并进入内存故障缓存。

解释规则：

| 次数 | 覆盖 | 含义 |
|---:|---:|---|
| 0 | 完整 | 真实零输入 |
| 0 | 0 | 缺失数据，不应画成零 |
| 任意 | 部分 | 部分时间有记录，图表需标识 |

## 11. 数据库设计

### 11.1 SQLite 设置

打开数据库后设置：

    PRAGMA journal_mode = WAL;
    PRAGMA synchronous = NORMAL;
    PRAGMA foreign_keys = ON;
    PRAGMA busy_timeout = 短而有限的毫秒数;

要求：

- 写事务尽量短；
- 查询使用只读连接或独立连接；
- 不从 UI 线程同步执行慢查询；
- 应用只允许单实例写入；
- 备份使用 SQLite 一致性备份 API，不直接复制运行中的主文件。

### 11.2 表结构

#### bucket_5m

| 字段 | 类型 | 说明 |
|---|---|---|
| bucket_start_utc | INTEGER PRIMARY KEY | UTC+0 对齐的 5 分钟起始 Unix 秒 |
| coverage_seconds | INTEGER NOT NULL | 0 至 300 |
| counts_json | TEXT NOT NULL | 稳定输入 ID 到 64 位计数的紧凑 JSON |
| updated_utc | INTEGER NOT NULL | 最近完整快照写入时间 |

#### bucket_1h

| 字段 | 类型 | 说明 |
|---|---|---|
| bucket_start_utc | INTEGER PRIMARY KEY | UTC+0 整点 Unix 秒 |
| coverage_seconds | INTEGER NOT NULL | 0 至 3600 |
| counts_json | TEXT NOT NULL | 稳定输入 ID 到 64 位计数的紧凑 JSON |
| updated_utc | INTEGER NOT NULL | 聚合或重写时间 |

#### metadata

| 字段 | 类型 | 说明 |
|---|---|---|
| key | TEXT PRIMARY KEY | 元数据键 |
| value | TEXT NOT NULL | 元数据值 |

至少保存：

- schema_version；
- first_capture_utc；
- application_version；
- last_compaction_utc；
- 其他不含敏感信息的必要状态。

#### migration_history

| 字段 | 类型 | 说明 |
|---|---|---|
| version | INTEGER PRIMARY KEY | 已应用模式版本 |
| applied_utc | INTEGER NOT NULL | 应用时间 |

### 11.3 counts_json

- 键使用稳定、短小、与显示语言无关的数字或短字符串输入 ID。
- 值使用 64 位非负整数。
- 只写非零项。
- 覆盖时间大于零但没有输入时写空对象。
- 序列化顺序保持稳定，便于测试和差异分析。
- 不在 JSON 中加入事件时间、设备信息或按键顺序。

示意：

    {
      "1": 120,
      "2": 18,
      "101": 45,
      "201": 7
    }

具体 ID 表必须作为版本化源文件维护，并有稳定性测试。已有 ID 不得复用为不同输入。

### 11.4 采用单桶单行的原因

首版不为每个键在每个时间桶写一行，而使用一个桶一行的紧凑 JSON，原因是：

- 5 分钟桶数量可控；
- 大量为零的键无需存储；
- 单次检查点只 UPSERT 一行；
- 数据库体积和写放大更小；
- 读取时间范围后在内存中聚合简单。

导出时再把 JSON 展开为行。

## 12. 数据保留与整点合并

### 12.1 默认策略

- 5 分钟明细默认保留 365 天。
- 超过 365 天的完整 UTC 小时，合并到 bucket_1h。
- 小时桶永久保留。
- 用户可选择“永久保留 5 分钟明细”。

### 12.2 合并规则

合并一律按照 UTC+0 整点进行：

1. 找出已超过保留期且完整覆盖一个 UTC 小时的 5 分钟桶。
2. 对该小时内最多 12 个 5 分钟桶逐输入 ID 求和。
3. coverage_seconds 求和并限制在 0 至 3600。
4. 以完整快照 UPSERT 对应小时桶。
5. 在同一受控流程中重新读取并校验小时桶。
6. 校验成功后删除已合并的 5 分钟桶。
7. 记录合并范围、行数、耗时和结果，不记录输入 ID 细节。

若小时内部分 5 分钟桶不存在，仍可合并已存在数据，但 coverage_seconds 会反映缺口。不得自动补零。

### 12.3 重复执行

- 合并任务必须幂等。
- 崩溃发生在写小时桶后、删 5 分钟桶前，重跑仍得到相同小时快照。
- 只有验证小时桶正确后才能删除 5 分钟明细。
- 删除失败时保留重复明细，查询层必须避免同一时间范围同时重复使用 5 分钟和小时桶。

### 12.4 查询层选择

查询范围同时跨越明细和归档时：

- 对仍存在 5 分钟明细的时段优先使用 5 分钟数据；
- 对已归档时段使用 1 小时数据；
- 严格划分时间边界；
- 不重复求和；
- UI 明示历史最小可用粒度为 1 小时。

## 14. 实体键盘与鼠标可视化

### 14.1 2.5D 首版尝试

参考图是 Blender 渲染效果，首版不引入三维引擎，也不追求完全复刻。先制作轻量 2.5D 原型：

- 近似俯视视角；
- 矢量键帽顶面和侧面；
- 轻微固定透视；
- 圆角和柔和阴影；
- 热力颜色作用于键帽；
- 按下时产生轻微压缩；
- 不提供相机旋转、真实材质、光照或三维模型。

2.5D 原型需要单独评审以下指标：

- 键名是否清晰；
- 数字是否清晰；
- 100% 至 200% DPI 是否稳定；
- 104 键是否拥挤；
- 低配置设备是否流畅；
- 热力颜色是否可辨；
- 实现和发布体积是否合理。

若视觉效果、可读性、DPI 或性能不达标，切换为纯 2D 轮廓。

### 14.2 渲染器接口

业务和布局不得依赖具体渲染方案。建议定义：

    IKeyboardRenderer
        RenderLayout(layout, heatmap, selection, animationState)
        HitTest(point)
        UpdateTheme(theme)
        UpdateScale(scale)

实现：

- KeyboardRenderer25D；
- KeyboardRenderer2D。

鼠标轮廓采用同类数据驱动和命中测试原则。

### 14.3 键位必须分离

实体键盘必须逐键绘制、逐键命中、逐键着色和逐键展示次数，不能把一行或一个区域合成一张不可交互图片。

至少满足：

- 独立键帽几何；
- 不同宽度键帽；
- 功能区、导航区、方向区和小键盘间距；
- 左右修饰键独立；
- 主区和小键盘独立；
- 75% 右侧 Home/End/PgUp/PgDn 竖列独立；
- 热力色和数字可以逐键更新；
- 点击选择精确到单键。

### 14.4 热力图

默认归一化：

    intensity = log(1 + count)

颜色语义：

- 零值：中性背景；
- 低频：蓝色；
- 中频：黄色；
- 高频：橙色。

键盘和鼠标分别计算颜色尺度，避免鼠标高频点击压低键盘对比度或反之。

提供：

- 相对尺度：当前范围内自动归一化，默认；
- 固定尺度：跨日期对比使用；
- 冰霜；
- 火焰；
- 海洋；
- 森林；
- 熔岩；
- 单色；
- 色觉友好。

首版不提供任意颜色停靠点编辑器。

### 14.5 显示优先级

窗口变窄时：

1. 保留实体键位拓扑；
2. 优先保留键名；
3. 空间不足时先隐藏键帽上的计数；
4. 鼠标区域移到键盘下方；
5. 导航可收缩为图标；
6. 不把键盘挤压到无法辨认。

## 15. 前台动画

### 15.1 启用条件

只有应用窗口处于前台且可见时播放实时动画：

- 键盘按下和释放；
- 鼠标区域按下；
- 滚轮方向；
- 今日数字更新。

当窗口隐藏到托盘、最小化、被其他应用遮盖为非活动窗口时，不播放输入动画，但后台统计继续。

### 15.2 动画效果

- 键帽按下：100 至 160 毫秒，2% 至 4% 的轻微下压和亮度变化。
- 松开：平滑回弹。
- 鼠标：对应区域短暂发光或压下。
- 滚轮：对应方向产生短促高亮。
- 数字：轻微淡入或滚动，不做大幅跳动。
- 不播放声音。

### 15.3 高频保护

- 动画状态按帧合并；
- 相同键的连续动画允许覆盖旧状态；
- 动画队列必须有界；
- 不为每个输入事件创建不可回收的动画对象；
- UI 跟不上时丢弃中间动画帧，不丢计数；
- 数字刷新可限制频率，最终数值必须准确；
- 动画异常不得影响采集线程。

### 15.4 可访问性

- 设置提供完整、减少、关闭三档。
- 检测并尊重 Windows 减少动画设置。
- 颜色不能作为唯一状态表达。
- 键名、数值、选中边框具有足够对比度。

## 16. 图表、缩放与采样粒度

### 16.1 成熟图表模块

使用 OxyPlot.Wpf 2.2.0，并通过薄适配层封装：

- 时间轴和序列构造；
- 缩放、平移和重置；
- 主题；
- 缺口和覆盖率；
- 数据点提示；
- 查询取消和防抖。

业务模型不直接依赖大量 OxyPlot 类型，便于将来升级或替换。

### 16.2 交互

- 鼠标滚轮以光标位置为中心缩放；
- 拖拽平移；
- 双击恢复默认范围；
- 提供加、减和重置按钮；
- 支持常见触摸板缩放和平移；
- 范围变化后 150 毫秒防抖；
- 新查询开始时取消旧查询；
- 新数据返回前保留旧图，避免闪白。

### 16.3 根据倍率确定采样粒度

图表按当前可见时间跨度选择采样粒度，目标显示约 200 至 600 个点：

| 可见时间跨度 | 采样粒度 |
|---|---|
| 小于等于 2 天 | 5 分钟 |
| 大于 2 天且小于等于 7 天 | 15 分钟 |
| 大于 7 天且小于等于 14 天 | 30 分钟 |
| 大于 14 天且小于等于 45 天 | 1 小时 |
| 大于 45 天且小于等于 120 天 | 6 小时 |
| 大于 120 天且小于等于 18 个月 | 1 天 |
| 大于 18 个月且小于等于 5 年 | 1 周 |
| 大于 5 年 | 1 月 |

规则：

- 仍有 5 分钟明细的时间段，最小显示粒度为 5 分钟。
- 已归档为小时桶的时间段，最小显示粒度为 1 小时。
- 15 分钟、30 分钟、6 小时、日、周、月均在查询时从现有桶精确求和。
- 不通过插值或平滑伪造统计值。
- 缺失覆盖画为空白或缺口。
- 部分覆盖的数据点需提供视觉提示和 tooltip 说明。

### 16.4 周和月

- 周按有效显示时区的自然周聚合，首版采用周一为一周起点。
- 月按有效显示时区自然月聚合。
- 同一 UTC 小时桶可能跨本地日边界，查询层需按时间重叠精确归属；在只剩小时桶的历史范围内，粒度精度上限为 1 小时，并在界面说明。

## 20. 数据目录与安装

### 20.1 目录关系

用户可自定义安装位置。应用可执行文件和数据库文件夹必须处于同一个父安装根目录内：

    用户选择的 InputAtlas 根目录
    ├─ InputAtlas.exe
    ├─ 运行依赖
    ├─ Licenses
    └─ Data
       ├─ inputatlas.db
       ├─ config.json
       ├─ Logs
       ├─ Backups
       └─ Exports

默认位置：

    %LocalAppData%\Programs\InputAtlas

允许示例：

    D:\Tools\InputAtlas

应用必须通过 AppContext.BaseDirectory 解析 Data 目录，不能依赖当前工作目录。

### 20.2 位置验证

安装器在确认位置时必须：

1. 解析绝对规范路径；
2. 确认路径是本地固定磁盘；
3. 创建测试文件；
4. 写入并刷新；
5. 重新读取；
6. 删除测试文件；
7. 确认没有其他 InputAtlas 实例使用同一 Data。

默认拒绝：

- Program Files 和其他需要管理员写入的系统目录；
- Windows 系统目录；
- UNC 网络路径；
- 映射网络盘；
- 只读位置；
- 无法完成写入、刷新、读取、删除探测的位置；
- 可移动磁盘。

同步文件夹可显示数据一致性警告，并要求用户再次确认后允许。

### 20.3 移动安装

- 首版不支持在应用运行期间直接移动数据目录。
- 用户需要通过重新运行安装器选择新位置。
- 移动前要求退出、保存并做一致性备份。
- 不允许两个安装实例共享同一 Data 文件夹。

### 20.4 安装器

使用 Inno Setup 7：

- PrivilegesRequired=lowest；
- 当前用户安装；
- x64；
- LZMA2 solid 压缩；
- 创建开始菜单快捷方式和卸载入口；
- 可选桌面快捷方式；
- 安装包内置 .NET 10 Desktop Runtime，不检测目标机器的全局运行时；
- 安装和首次启动均不得联网下载运行时。

### 20.5 无便携版

首版只提供安装器版本，以保证：

- 数据路径规则一致；
- 自启动和卸载行为明确；
- 升级可迁移；
- 单实例和日志路径稳定。

## 22. 导出、备份、恢复与删除

### 22.1 CSV 导出

支持选择：

- 日期范围；
- 5 分钟、1 小时或 1 天导出粒度；
- 键盘、鼠标按键、滚轮或全部类别。

CSV 至少包含：

- bucket_start_utc；
- display_time；
- display_timezone；
- granularity；
- category；
- input_id；
- display_name；
- count；
- coverage_seconds；
- coverage_ratio。

导出过程把 counts_json 展开为行。不得导出设备信息、事件顺序和逐事件时间戳。

### 22.2 备份

- 用户选择任意可写的目标位置。
- 使用 SQLite 一致性备份 API。
- 备份前完成受控检查点。
- 备份文件包含数据库和必要的版本说明。
- 设置文件可作为独立附属文件或进入备份包。
- 完成后显示路径、大小、时间和结果。

### 22.3 恢复

首版只支持完整替换，不支持合并：

1. 验证备份格式和数据库完整性；
2. 验证 schema version 是否受当前版本支持；
3. 暂停并注销 Raw Input；
4. 自动备份当前数据；
5. 关闭数据库连接；
6. 用事务化或原子替换方式恢复；
7. 重新打开并执行完整性检查；
8. 成功后恢复采集；
9. 失败则恢复原数据库。

### 22.4 删除统计

支持：

- 删除单日；
- 删除日期范围；
- 删除全部统计数据。

影响：

- 已活跃天数重新计算；
- 已使用天数不变；
- 设置、配列和首次使用时间不变；
- 删除操作事务化；
- 删除前默认创建一致性备份。

### 22.5 完整重置

完整重置删除：

- 数据库；
- 配置；
- 日志；
- 内部备份；
- 首次使用时间；
- 开机启动配置；
- 首次提示状态。

完成后回到首次引导。

破坏性操作规则：

- 默认先创建最多保留 3 份的安全备份；
- 备份失败时默认阻止继续；
- 只有用户明确选择“跳过备份继续”才执行；
- 删除 Data 内文件前解析并验证精确绝对路径；
- 不对工作区根目录、用户目录、磁盘根或未解析变量执行递归删除；
- 操作结果明确说明删除内容和可恢复性。

## 23. 升级、迁移与卸载

### 23.1 升级

- 安装器保持固定 AppId。
- 升级前通过本地 IPC 请求运行实例保存并退出。
- Data 和设置默认保留。
- 数据库模式使用递增 schema_version。
- 每次迁移在事务中逐版本执行。
- 迁移前自动创建一致性备份。
- 迁移失败时回滚，不注册 Raw Input，不继续写入旧数据库。
- 记录迁移版本、耗时和错误码，不记录输入数据细节。

### 23.2 降级

- 不支持直接打开更高 schema version 的数据库。
- 检测到版本过高时只显示明确错误和恢复建议。
- 用户可安装兼容版本或从旧备份恢复。

### 23.3 卸载

- 默认删除程序文件，保留 Data。
- 卸载器提供明确的“同时删除所有统计和设置”选项，默认不勾选。
- 删除全部数据前再次确认精确目录。
- 卸载不触发网络请求。

### 23.4 签名和完整性

- 个人首版可暂不购买代码签名证书。
- 每次发布生成 SHA-256 校验文件。
- 生成构建清单，记录版本、提交、工具链、依赖和文件哈希。
- 面向公众分发前再加入可信代码签名。

## 24. 日志与诊断

### 24.1 日志实现

实现轻量、本地、异步、滚动日志：

- UTF-8，无 BOM；
- 单文件最大 2 MB；
- 最多 5 个文件；
- 总量约 10 MB；
- 有界日志队列；
- 队列满时丢弃低优先级日志，不阻塞采集；
- 后续汇总记录丢弃的日志条数；
- Release 默认 Information 级别；
- 设置中可开启最长 24 小时诊断模式，之后自动恢复。

### 24.2 细粒度运行日志

按 AGENTS.md 约束，代码需要细粒度日志。细粒度指生命周期和操作阶段充分，不是记录每次输入。

需要记录：

- 启动、版本、进程位数、运行时、有效时区；
- 单实例 mutex 和 named pipe 建立、激活和超时；
- Raw Input 注册、注销、恢复、暂停；
- 会话锁定、解锁、睡眠、恢复；
- 5 分钟桶切换；
- 检查点开始、快照桶数、耗时、结果；
- 数据库打开、WAL、重试、故障缓存大小；
- 模式迁移、备份、恢复、删除和整点合并；
- 页面载入和图表查询范围、粒度、点数、耗时；
- 设置变更和自启动配置；
- 导出范围、输出行数、耗时和结果；
- 未处理异常；
- 性能降级、队列积压和丢弃日志汇总。

### 24.3 禁止的日志粒度

不得记录：

- “用户按下了 A”；
- 扫描码或虚拟键码；
- 鼠标某次点击；
- 单次滚轮方向；
- 任何输入事件时间序列；
- 当前输入设备；
- 当前窗口或进程；
- 用户内容。

## 25. 性能与可靠性目标

### 25.1 资源预算

| 指标 | 目标 |
|---|---:|
| 发布目录大小 | 不大于 10 MB |
| 托盘后台工作集 | 不大于 70 MB |
| 主窗口打开工作集 | 不大于 150 MB |
| 后台空闲 CPU | 不大于 0.2% |
| 8 kHz 鼠标移动压力 CPU | 不大于 1% |
| Raw Input 回调 P99 | 不大于 50 微秒 |
| 任一 Raw Input 回调 | 小于 1 毫秒 |
| 30 秒检查点 P95 | 不大于 100 毫秒 |
| 冷启动到开始采集 | 不大于 2 秒 |
| 托盘打开已缓存页面 | 不大于 500 毫秒 |
| 前台数字可见延迟 | 不大于 250 毫秒 |
| 正常退出保存 | 不大于 1 秒 |

这些数值在固定本地测试机的 Release x64 构建上验收。CPU 指标需注明测试机型号、Windows 版本、采样窗口和测量工具。

### 25.2 可靠性

- 所有后台队列有界。
- 所有数据库写入幂等。
- 所有破坏性数据操作事务化或可回滚。
- UI、图表、日志失败不能终止采集。
- 数据库持续不可用达到内存上限时主动暂停，不静默丢数据。
- 采集失败时覆盖率停止增加。
- 应用异常重启后可从最近检查点恢复。

### 25.3 压力下的降级顺序

系统压力增大时按以下顺序降级：

1. 降低数字刷新频率；
2. 合并或丢弃中间动画帧；
3. 降低图表刷新频率；
4. 推迟非关键合并和维护；
5. 丢弃低优先级日志；
6. 保持输入计数和关键检查点优先。

## 26. 本地 CI/CD

### 26.1 原则

完全在本地 Windows 机器运行，不依赖 GitHub Actions 或其他云服务。统一入口：

    pwsh ./build.ps1 <command>

build.ps1 是开发机、Git hook、计划任务和正式发布的唯一构建事实来源。

所有包含中文的 PowerShell 脚本必须先执行以下初始化，并在初始化前不输出中文：

    chcp 65001 > $null
    [Console]::OutputEncoding = [System.Text.Encoding]::UTF8
    [Console]::InputEncoding  = [System.Text.Encoding]::UTF8
    $OutputEncoding           = [System.Text.Encoding]::UTF8
    $PSDefaultParameterValues['*:Encoding'] = 'UTF8'

优先使用 PowerShell 7。若检测到主版本低于 7，应以 Windows PowerShell 5.1 兼容方式运行并显式指定 UTF-8 文件编码。

### 26.2 构建命令

    pwsh ./build.ps1 check
    pwsh ./build.ps1 test
    pwsh ./build.ps1 benchmark
    pwsh ./build.ps1 ci
    pwsh ./build.ps1 package
    pwsh ./build.ps1 release -Version 1.0.0

建议语义：

| 命令 | 内容 |
|---|---|
| check | 环境、格式、静态分析、Release 编译 |
| test | 单元和常规集成测试 |
| benchmark | 输入热路径、数据库、查询、资源性能 |
| ci | check + test + 关键性能冒烟 + publish + 体积门禁 |
| package | 生成本地安装包和校验文件 |
| release | 完整 CI、版本校验、安装包、哈希、构建清单 |

### 26.3 本地触发

- pre-commit：快速格式、静态分析、必要单测和编译。
- pre-push：完整 check 和 test。
- Windows 计划任务：夜间执行 ci 和 benchmark。
- 正式发布：开发者显式执行 release。
- 结果和制品保存在工作区下受控的 artifacts 目录。

Git hook 只调用 build.ps1，不复制构建逻辑。

### 26.4 CI 流程

1. 检查 pwsh、dotnet、Inno Setup 和目标运行时环境。
2. 以锁定依赖方式 restore。
3. 格式检查。
4. 静态分析。
5. Release x64 编译，警告视为错误。
6. 单元测试。
7. SQLite 集成测试。
8. Raw Input 录制样本重放测试。
9. UI 模型和布局快照测试。
10. 关键性能测试。
11. framework-dependent publish。
12. 计算发布目录大小并执行 10 MB 硬门禁。
13. 生成 Inno Setup 安装器。
14. 生成 SHA-256 和构建清单。
15. 输出可机器读取和可读的结果摘要。

### 26.5 依赖可重复性

- NuGet 使用 lock file。
- CI 使用 locked mode。
- Inno Setup 版本固定。
- OxyPlot 版本固定。

## 29. 异常和边界处理

### 29.1 系统时间跳变

- UTC 桶边界基于系统 UTC 时间。
- coverage_seconds 主要使用单调计时，防止系统时钟回拨造成负覆盖。
- 检测大幅时钟跳变后结束当前快照、重新计算桶并记录生命周期日志。
- 不重复写入相同时间段增量。

### 29.2 数据库损坏

- 启动时执行轻量完整性检查策略。
- 检测到损坏时不直接覆盖原文件。
- 暂停采集并提示从备份恢复或导出可恢复内容。
- 保留损坏文件的只读副本供用户处理。

### 29.3 磁盘空间不足

- 保存失败进入数据库退避和内存缓存。
- 状态栏明确显示原因。
- 达到缓存上限后暂停采集。
- 日志滚动不能无限占用空间。

### 29.4 UI 崩溃隔离

可在同一进程中通过线程和异常边界隔离，但首版不要求多进程。UI 未处理异常不应在可以安全恢复时破坏数据库。所有状态保存和关闭必须有明确异常路径。

### 29.5 计数溢出

- 所有计数使用 64 位有符号整数的非负范围。
- 求和使用检查或饱和策略并记录严重错误。
- UI 格式化大数时保持精确 tooltip。
